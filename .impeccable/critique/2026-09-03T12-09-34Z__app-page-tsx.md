## Design Specificity Verdict

LLM assessment: the system is authored for this product; the entrances are not. Genuinely unliftable: a `Level` union type that makes percentages structurally impossible; a contact state machine with no "sent" state; `featuredProject` computed as `find(p => p.featured && !p.placeholder)`, so the site cannot promote fake work to its hero slot. That is a position expressed in the type system.

Liftable today, unchanged: the hero (animate-ping dot → giant name → bullet-separated role line → two pills → terminal → scroll arrow is stock developer-portfolio), the SectionHeader used identically eight times, the three-icon workflow cards, the contact split. The eleven section compositions genuinely differ on column spans, but they share one header, one panel recipe and identical reveal timing — they differ on paper and rhyme in the eye.

Deterministic scan: detect.mjs exit 2, 31 findings — 29 x design-system-font-size, 1 x codex-grid-background, 1 x design-system-radius. The detector caught real drift the design review missed: 11 distinct font sizes against a 6-step documented ramp (0.72 / 0.78 / 0.8 / 0.82 / 0.85 / 0.9 / 0.94rem all ad-hoc), with Footer.tsx using 0.82rem and 0.85rem in the same component.

False positives: codex-grid-background (globals.css:118) — DESIGN.md declares the texture a first-class system property, measured opacity 0.035/0.05 sits at or below the documented ceiling, and the rule's own exception covers blueprint surfaces. design-system-radius (globals.css:84) is a weak hit — 3px on a :focus-visible outline, cosmetically identical to the 4px token.

## Overall Impression

The honesty machinery is the best thing here and currently the thing hurting it most. Roughly 35–48 explicit placeholder markers render on one page, making the badge the most frequent visual element on the site — more common than any real content element. Three labelled gaps read as discipline; thirty-five read as an empty building with excellent signage. Biggest opportunity: the one thing that unambiguously exists is this codebase, and it is the least-featured asset on the site.

## What's Working

1. The honesty constraint lives in the type system, not in discipline. `placeholder: true` flows through five separate render paths and produces the same badge in all of them.
2. Elevation and accent discipline, verified: zero box-shadow across the entire codebase, three neutral steps, two hairline weights, backdrop-blur on exactly the four surfaces that genuinely float.
3. Reduced motion as baseline rather than fallback — four independent mechanisms, correctly reasoned.

## Priority Issues

### [P0] Maintainer build instructions rendered as product copy
Nine project descriptions begin "PLACEHOLDER — REPLACE WITH REAL PROJECT."; case-study fields read "[PLACEHOLDER] Describe the problem"; three components print file paths (/data/skills.ts, /data/site.ts, /data/projects.ts) to visitors.
Why it matters: a badge is a stance toward the visitor; a TODO note is an unfinished admin panel left open in public. A peer reads "REPLACE WITH REAL PROJECT" and concludes he shipped a template and never filled it in — the opposite of the judgment the site argues for.
Fix: keep every badge, delete every instruction, write visitor-facing copy for each gap. Maintainer notes belong in the /data comments.
Suggested command: /impeccable clarify

### [P1] Hero and six sections ship as opacity: 0 in the server HTML
Framer Motion writes `initial` into SSR markup. With JS blocked or slow, the wordmark is invisible and About, FeaturedCase, Cybersecurity, Developer, Journey and Philosophy are blank. Reduced-motion users are affected too, since useReducedMotion() resolves non-reduced during server render.
Why it matters: the stated arrival path is a cold mobile load from a shared link. It also contradicts the site's own displayed proof-of-judgment: "Motion is the enhancement, never the requirement."
Fix: apply the pattern Terminal.tsx already uses — render final state in HTML, layer motion on after mount via a js-ready class.
Suggested command: /impeccable harden

### [P1] The accessibility floor fails in four measured places
label-mono at 11px in --c-faint is 3.38:1 dark / 3.35:1 light — fails AA in both themes, and carries every section index, metadata key, caption and the whole footer. Input borders are 1.18:1 against the page. The primary CTA drops 16.5:1 → 3.69:1 on hover. Light-theme ice is 4.16:1 on success text. Plus 15 touch targets under 44px (footer links ~20px) and two aria-modal dialogs that do not trap Tab.
Why it matters: DESIGN.md calls the mono index "the site's spine"; PRODUCT.md makes keyboard and screen-reader support binding.
Suggested command: /impeccable audit

### [P1] The one real project is shown three times; 19 filter chips break the layout
this-portfolio renders as the largest grid card, then again immediately below in FeaturedCase with identical title and description; the two security projects appear a third time. Six of eight project categories and six of nine creative categories contain exactly one item — filtering to any leaves 4–8 of 12 columns empty or an entirely blank masonry column.
Fix: drop the featured card from the grid (it is the section below); replace 19 chips with three — Real work / In progress / Everything.
Suggested command: /impeccable distill

### [P2] Type-ramp drift plus two deployment blockers
11 font sizes against 6 documented steps (29 detector hits). site.url is still https://example.com, feeding every canonical, the sitemap and OG. twitter:card is summary_large_image with no OG image, so the link preview on the primary arrival path is blank.
